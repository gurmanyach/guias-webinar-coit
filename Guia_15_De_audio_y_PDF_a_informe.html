De un audio o un PDF a un informe

Las herramientas pequeñas que hacen el trabajo sucio: transcribir una grabación, entender un PDF complicado —con sus tablas, sus fórmulas y su numeración—, reconocer un escaneado y comprobar lo que generas. Con el código, listo para copiar.

Nivel: técnicoLectura: ~25 min Todo el código se ejecutó antes de publicarlo

El recorrido, de un vistazo

Dos entradas muy distintas —una grabación y un PDF— acaban en el mismo sitio: un texto con estructura que una IA puede usar para redactarte un borrador. Lo difícil no es la IA: es llegar a ese texto sin perder por el camino las tablas, los números y el orden.

La regla que ahorra disgustos

Primero se extrae, después se pregunta. El error más común es darle el PDF entero a una IA y pedirle la tabla: es justo donde más inventa. El camino correcto es sacar la tabla con un programa —que no inventa, o falla de forma visible— y pasarle a la IA el resultado ya estructurado.

Qué hace falta instalar, en total

Menos de lo que parece. Todo lo de esta guía se monta con esto:

pip install faster-whisper      # transcripción de audio
pip install pymupdf pdfplumber  # leer PDF: texto, estructura y tablas
pip install pytesseract pillow  # OCR de PDF escaneados
pip install playwright          # navegador, para comprobar lo que generas
playwright install chromium     # descarga el navegador (una vez)

Y dos programas que no son de Python: ffmpeg (para el audio) y tesseract (para el OCR). En Windows se instalan con winget install Gyan.FFmpeg y winget install UB-Mannheim.TesseractOCR; en Linux, con el gestor de paquetes de la distribución.

Transcribir una grabación

Grabas la visita de obra con el móvil y quieres el acta. Esto es lo que hay que hacer, y lo que cuesta de verdad.

El código mínimo que funciona

from faster_whisper import WhisperModel

# "base" es el equilibrio para empezar; en un portátil normal, sin tarjeta gráfica.
modelo = WhisperModel("base", device="cpu", compute_type="int8")
segmentos, info = modelo.transcribe(
    "visita_obra.m4a",
    language="es",        # si lo sabes, dilo: evita que se equivoque de idioma
    vad_filter=True,      # se salta los silencios: más rápido y menos alucinación
)

print(f"idioma: {info.language} (confianza {info.language_probability:.2f})")

with open("transcripcion.txt", "w", encoding="utf-8") as f:
    for s in segmentos:
        # las marcas de tiempo valen oro: te llevan al minuto exacto de la grabación
        f.write(f"[{s.start:7.1f} → {s.end:7.1f}]  {s.text.strip()}\n")
Medido, no estimado

Ejecutado el 16/09/2026 con faster-whisper 1.2.1, modelo base, en el procesador (sin tarjeta gráfica): 10 segundos de audio en español, transcritos en 6,1 segundos, con el idioma detectado con confianza 1,00. Es decir: una reunión de una hora se transcribe en unos 35 minutos en un portátil normal, y en unos pocos minutos si hay tarjeta gráfica.

Qué modelo elegir

ModeloCuándo usarloMemoria aproximada
baseNotas personales, audio limpio, ir rápido~1 GB
smallEl equilibrio razonable para trabajo real~2 GB
large-v3Acta que va a leer un cliente, audio con ruido de obra~5 GB

Si el ordenador tiene tarjeta gráfica, cambia device="cpu" por device="cuda" y compute_type="int8" por "float16": va entre cinco y diez veces más rápido.

Quién dice qué

Si necesitas separar interlocutores —«esto lo pidió la propiedad, no la dirección facultativa»—, eso es diarización, y la hace otra herramienta: WhisperX, que combina la transcripción con pyannote.audio. Requiere aceptar las condiciones del modelo en su web y una clave gratuita. Para un acta interna, el resultado sin diarizar suele bastar; para una discusión contractual, merece la pena.

Antes de grabar a alguien

Grabar una reunión con terceros exige avisar a los presentes. Y si la grabación se sube a un servicio en la nube, esos datos salen de tu despacho: para reuniones con datos de cliente, la transcripción en local —que es exactamente lo que hace este código— es la única respuesta cómoda.

Del texto al informe

Ya tienes la transcripción. Ahora viene la parte donde la IA sí aporta: convertir hora y media de conversación en un acta con acuerdos y tareas.

La petición que funciona

El fallo típico es pedir «hazme un resumen». Sale un resumen bonito e inútil. Lo que sirve es pedir una estructura concreta y prohibir explícitamente inventar:

PETICION = """Eres el secretario técnico de una reunión de obra. A partir de la transcripción
literal que te doy, redacta el acta con esta estructura exacta:

1. ASISTENTES (solo los que se nombren en el texto)
2. ACUERDOS: cada uno en una línea, con el minuto donde se acuerda
3. TAREAS: qué, quién y para cuándo. Si no se dice el plazo, escribe "sin plazo"
4. DUDAS: lo que quedó sin cerrar

Reglas que no puedes saltarte:
- No añadas nada que no esté en la transcripción. Nada.
- Si algo no está claro, ponlo en DUDAS en lugar de deducirlo.
- Cita siempre el minuto entre corchetes.

TRANSCRIPCIÓN:
"""

texto = open("transcripcion.txt", encoding="utf-8").read()
# ...y esto se le manda al asistente que uses, pegando PETICION + texto.

Y lo mismo, contra un modelo local

Exactamente igual, pero sin que el texto salga de tu red:

import requests   # el modelo local se habla igual que cualquier servicio web

respuesta = requests.post(
    "http://TU-SERVIDOR:11434/api/generate",   # Ollama, en tu propia máquina
    json={
        "model": "qwen3:8b",
        "prompt": PETICION + texto,
        "stream": False,
        "options": {"temperature": 0.2},   # bajo: queremos fidelidad, no creatividad
    }, timeout=600,
)
open("acta.md", "w", encoding="utf-8").write(respuesta.json()["response"])
Las tres reglas del texto de la petición
  • Di el formato exacto que quieres, apartado por apartado.
  • Obliga a citar el minuto. Es lo que te permite comprobarlo en diez segundos, y lo que hace que el modelo se sujete al texto.
  • Dale permiso para no saber. «Si algo no está claro, escríbelo en DUDAS» es la frase que más alucinaciones evita, porque le das una salida honesta.

La estructura de un PDF difícil

Un reglamento o un pliego no es un texto plano: es una jerarquía —1, 1.1, 1.1.a— y perderla es perder el sentido. Esto es lo que hay que hacer, en orden.

Paso 1: mira si el PDF ya trae su índice

Muchos lo traen y casi nadie lo aprovecha. Es gratis y exacto:

import fitz   # el paquete se llama pymupdf, pero se importa como fitz

doc = fitz.open("reglamento.pdf")
indice = doc.get_toc()          # [[nivel, título, página], ...]

for nivel, titulo, pagina in indice:
    print("  " * (nivel - 1) + f"{titulo}  ......  pág. {pagina}")

Si devuelve entradas, ya has terminado. Si devuelve cero —que es lo que pasó al probarlo con un manual técnico real de 322 páginas— hay que reconstruirla.

Paso 2: reconstruir la jerarquía

Dos señales, y conviene usar las dos porque se corrigen entre sí: la numeración escrita (1.2.3) y el tamaño de la letra (los títulos son más grandes o van en negrita).

import fitz, re, collections

doc = fitz.open("reglamento.pdf")

# (a) ¿cuál es el tamaño del texto NORMAL? El más frecuente, por número de caracteres.
tam = collections.Counter()
for pag in doc:
    for bloque in pag.get_text("dict")["blocks"]:
        for linea in bloque.get("lines", []):
            for trozo in linea["spans"]:
                if trozo["text"].strip():
                    negrita = bool(trozo["flags"] & 2**4)
                    tam[(round(trozo["size"], 1), negrita)] += len(trozo["text"])

cuerpo = tam.most_common(1)[0][0][0]     # tamaño del cuerpo del texto

# (b) es título si mide más que el cuerpo, o si empieza por numeración jerárquica
NUMERACION = re.compile(r"^\s*(\d+(?:\.\d+)*)\s+(\S.{2,70})$")

titulos = []
for n, pag in enumerate(doc, start=1):
    for bloque in pag.get_text("dict")["blocks"]:
        for linea in bloque.get("lines", []):
            texto = "".join(t["text"] for t in linea["spans"]).strip()
            if not texto or len(texto) > 90:
                continue
            grande = linea["spans"][0]["size"] > cuerpo + 0.4
            m = NUMERACION.match(texto)
            if m or grande:
                # el nivel sale de contar los puntos: "4.2.1" es nivel 3
                nivel = m.group(1).count(".") + 1 if m else 1
                titulos.append((nivel, texto, n))

for nivel, texto, pagina in titulos[:30]:
    print("  " * (nivel - 1) + f"{texto}   [pág. {pagina}]")
Probado

Sobre un manual técnico de 322 páginas sin índice incorporado, este método reconstruyó 24 encabezados numerados en las primeras 40 páginas. Y el censo de tamaños dejó claro cuál era el cuerpo del texto —12 pt— frente a los títulos.

Las tablas: donde todo el mundo se estrella

Esta pestaña es la más importante de la guía, y la escribo con un fallo propio delante, porque enseña más que el código que funciona.

Primer intento: la configuración por defecto

import pdfplumber

with pdfplumber.open("catalogo.pdf") as pdf:
    for pagina in pdf.pages:
        for tabla in pagina.extract_tables():      # busca LÍNEAS dibujadas
            print(tabla)

Sobre un manual de fabricante real, esto devolvió cero tablas en 30 páginas. No porque no las hubiera: porque el método por defecto busca líneas, y muchísimas tablas técnicas no tienen bordes dibujados.

Segundo intento: buscar por alineación de texto

CONFIG = {
    "vertical_strategy": "text",      # deduce las columnas por cómo se alinea el texto
    "horizontal_strategy": "text",
    "text_tolerance": 2,
    "intersection_tolerance": 5,
}
tablas = pagina.extract_tables(CONFIG)

Ahora salieron 26 tablas… y la primera era un párrafo de prosa troceado en columnas. Esto es peor que no encontrar nada: es basura con formato de dato.

La pieza que falta: comprobar que lo extraído ES una tabla

import re, statistics

def limpia(t):
    """Quita filas y columnas completamente vacías. Sin esto, el filtro de abajo
       descarta tablas buenas: lo comprobé, y me pasó."""
    t = [f for f in t if any((c or "").strip() for c in f)]
    if not t:
        return t
    ancho = max(len(f) for f in t)
    vivas = [i for i in range(ancho)
             if any(((f[i] if i < len(f) else "") or "").strip() for f in t)]
    return [[(f[i] if i < len(f) else "") for i in vivas] for f in t]

def es_tabla(t):
    """¿Esto es una tabla de verdad, o es prosa troceada en columnas?"""
    if len(t) < 3 or len(t[0]) < 3:
        return False
    llenas = [sum(1 for c in f if (c or "").strip()) for f in t]
    if statistics.mean(llenas) < len(t[0]) * 0.6:      # demasiados huecos
        return False
    celdas = [(c or "").strip() for f in t for c in f if (c or "").strip()]
    if not celdas or statistics.mean(len(c) for c in celdas) > 18:
        return False                                    # celdas largas = es prosa
    numericas = sum(1 for c in celdas if re.fullmatch(r"[-+]?[\d.,]+\s*%?", c))
    return numericas / len(celdas) >= 0.3               # una tabla técnica tiene números

# uso:
for bruta in pagina.extract_tables(CONFIG):
    tabla = limpia(bruta)
    if es_tabla(tabla):
        for fila in tabla:
            print(" | ".join((c or "") for c in fila))
El fallo que cometí, y cómo lo cacé

Mi primera versión de ese filtro rechazaba también la tabla buena. Lo descubrí porque hice la prueba obligatoria: fabriqué un PDF con una tabla numérica que yo ya conocía y comprobé si el filtro la aceptaba. No lo hacía.

La causa: la extracción devuelve filas y columnas vacías de relleno, y yo estaba midiendo «columnas huecas» sobre la tabla sucia. Hay que limpiar antes de juzgar. Con la limpieza puesta: la tabla conocida se recupera intacta —5 filas × 7 columnas, 86 % de celdas numéricas— y las 54 candidatas de prosa de dos manuales distintos siguen descartándose, todas.

La lección vale para cualquier extractor que escribas: un filtro hay que probarlo con algo que SÍ debe pasar y con algo que NO debe pasar. Si solo pruebas una de las dos cosas, no sabes si filtra o si simplemente dice que no a todo.

Fórmulas, figuras y PDF escaneados

Las fórmulas mienten en la capa de texto

Si copias una fórmula de un PDF y la pegas, muchas veces sale desordenada o con símbolos cambiados. No es cosa tuya: las fórmulas se dibujan con tipografías especiales y, al extraer el texto «plano», los símbolos salen en el orden del dibujo, no en el de la lectura.

Regla de la casa, aprendida a base de errores

Una fórmula de un documento normativo no se extrae nunca de la capa de texto plana. Hay que mirarla en crudo, símbolo a símbolo, y contrastarla con la imagen. Si vas a usar una fórmula para calcular algo que firmas, transcríbela mirándola.

import fitz

pagina = fitz.open("norma.pdf")[24]

# "rawdict" da cada carácter por separado, con su tipografía y su posición:
# es la única forma de ver qué símbolo hay DE VERDAD en una fórmula.
for bloque in pagina.get_text("rawdict")["blocks"]:
    for linea in bloque.get("lines", []):
        for trozo in linea["spans"]:
            if "Symbol" in trozo["font"] or "Math" in trozo["font"]:
                simbolos = "".join(c["c"] for c in trozo["chars"])
                # el código del carácter es lo que no engaña
                codigos = [hex(ord(c["c"])) for c in trozo["chars"]]
                print(trozo["font"], simbolos, codigos)

Cuando el PDF es una foto

Un PDF escaneado no tiene texto: tiene una imagen de un texto. Para eso está el OCR — reconocimiento óptico de caracteres—, y funciona mejor de lo que la gente cree si se le da resolución suficiente:

import fitz, pytesseract
from PIL import Image
import io

doc = fitz.open("escaneado.pdf")
texto_total = []

for n, pagina in enumerate(doc, start=1):
    if pagina.get_text().strip():
        texto_total.append(pagina.get_text())      # esta página SÍ tiene texto: no hace falta OCR
        continue
    # 300 ppp: por debajo, el reconocimiento empeora mucho
    pix = pagina.get_pixmap(dpi=300)
    img = Image.open(io.BytesIO(pix.tobytes("png")))
    texto_total.append(pytesseract.image_to_string(img, lang="spa"))
    print(f"página {n}: reconocida por OCR")

open("texto.txt", "w", encoding="utf-8").write("\n\n".join(texto_total))
Probado el 16/09/2026

Con tesseract 5 y el idioma español, sobre una imagen con texto técnico, leyó sin un solo error «Aislamiento DnT,w = 52 dBA» y «art. 10.1 del RD 346/2011». El único fallo fue confundir un separador «·» con «:». Conclusión práctica: los números y las referencias salen bien; revisa la puntuación rara.

Dos detalles que marcan la diferencia: pedir 300 puntos por pulgada al rasterizar (con menos, el OCR se despeña) y decirle el idioma con lang="spa".

El navegador que comprueba tu trabajo

Esta es la herramienta menos conocida de todas y, para quien genere documentos o páginas, la que más disgustos evita: un navegador que se abre solo, sin ventana, y comprueba que lo que has generado se ve como debe.

Para qué sirve, en concreto

  • Abrir el documento que acabas de generar y comprobar que no da errores.
  • Hacerle una captura para verlo sin abrirlo a mano.
  • Comprobar que funciona en modo oscuro y en un móvil.
  • Y lo más útil: comprobar que no necesita internet para verse bien.
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    navegador = p.chromium.launch()
    # offline=True: si la página necesita internet para verse, FALLA aquí y no delante del cliente
    ctx = navegador.new_context(viewport={"width": 1280, "height": 900}, offline=True)
    pagina = ctx.new_page()

    errores = []
    pagina.on("pageerror", lambda e: errores.append(str(e)))

    pagina.goto("file:///C:/informes/informe.html")
    pagina.screenshot(path="comprobacion.png", full_page=True)

    print("errores:", errores or "ninguno")
    navegador.close()
Por qué esto importa más de lo que parece

Las guías que estás leyendo se comprobaron así, una por una, antes de publicarlas: cada página abierta en claro, en oscuro y a tamaño de móvil, con la red desconectada a propósito. Así se descubrió que una de ellas cargaba un componente de internet y, sin conexión, se quedaba en blanco. Ningún repaso a ojo lo habría encontrado.

Cómo se instala

pip install playwright
playwright install chromium

Ese playwright install chromium descarga un navegador propio, independiente del que tengas. Ocupa unos cientos de megas y se hace una sola vez.

El orden por el que empezar, si empiezas hoy
  1. PyMuPDF. Una tarde. Es la que más veces vas a usar.
  2. La transcripción. Otra tarde, y el ahorro se nota desde la primera visita de obra.
  3. El resto, cuando te haga falta: el OCR solo si recibes escaneados, y el navegador solo si generas documentos.

Y no montes las cinco cosas a la vez «por tenerlas»: monta la que resuelva el problema que tuviste la semana pasada.

Lo que no te va a funcionar a la primera
  • El audio del móvil no siempre está en un formato que la herramienta entienda directamente: ahí es donde entra ffmpeg, que convierte casi cualquier cosa.
  • Los PDF firmados o protegidos pueden no dejar extraer texto. Es una restricción del fichero, no un fallo tuyo.
  • La primera vez que ejecutes la transcripción se descargará el modelo: tarda, y necesita conexión. Después ya funciona sin internet.
